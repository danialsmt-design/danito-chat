Building a parts-verification / interlock system for Sony SMT chip mounters (like JUKI's "parts verification" concept). Goal: when a machine hits a parts-exhaust, identify the feeder + part, and prompt the operator to scan the exhausted reel and the new reel to confirm the replacement is correct.

**Architecture (confirmed 2026-07-16):**
- 6 SMT lines. **1 line = 4 Sony machines** (F130 / F209). **One verification PC per line** (6 PCs, 24 machines total).
- Each machine ↔ PC by **RS-232C serial** — 4 serial ports per PC (4-port card or USB-RS232). Total 24 serial links.
- Each line PC has a **handheld 2D barcode scanner** (USB) and a **reserved folder** where the operator manually drops the feeder→part mapping file (they will point to the folder later).
- All 6 line PCs → **1 central material control / parts control PC** via LAN switch.
**Parts control PC role (emerging):** holds a **reel database keyed by unique reel ID** (fields include quantity-on-reel), and is the home of the central badge master. On every Mode B parts change, once the new reel is verified & loaded, the line PC sends the new reel's **unique ID → parts control PC → retrieves the qty of parts on that reel** (registers "this reel + starting qty now loaded at this feeder"). Purpose = reel inventory / quantity tracking, reel ID as key.
**Remaining-count tracking (required):** keep a remaining component count per feeder (starting qty from parts control PC, draws down as machine places parts). On **every parts change OR exhaust event, record the remaining count per feeder** — so a reel removed early (parts still on it) is captured, not just empties. Removed reel's remaining written back to parts control PC against its reel ID (partial reel returns to stock with accurate count).
**Live remaining-count tracking (per feeder):** starting qty from parts control (reel-ID lookup); then **auto-decrement on every board completion** — machine sends real-time **R0** (R0CT continuous / R0EP step-cycle) per finished board; on each R0, subtract each feeder's **mounted-per-board count** (how many placements that feeder makes per board). So `remaining = starting − (mounted_per_board × boards_done)`. Approaches 0 → parts-out (R2E03).
**Manual key-in** = the operator types the **actual remaining** when a reel comes off (change/exhaust) to reconcile/correct the auto count and return the partial reel to stock (recorded against reel ID → parts control). Line PC needs on-screen numeric entry.
**Mounted-per-board source = SELECTABLE at setup (per line/machine): File OR NC.** Only THIS count is selectable — the expected part number for verification ALWAYS comes from the operator's feeder→part file (only barcode-matchable source; machine data only has Sony Part ID, not the reel's part-number barcode). Feeder list/sequence also from the operator's file.
- **File source:** a `qty-per-board` column added to the operator's feeder→part file (no serial upload for counting).
- **NC source (⚠️ REVISED 2026-07-23 after live test — HARDER than assumed on SI-F):** these are SI-F machines. **C1P over serial only exposes the whole `.PW4` bundle, ZIP-COMPRESSED binary** (not tidy line-by-line D0 text; NC data is a file INSIDE the zip). Requesting `.NC4`/`.NCA` was rejected `A4E01`. Retrieval = pull binary D0 frames → reassemble → unzip → parse NC file. **AND `C1P` FREEZES THE OPERATOR PANEL while running** ("operation of the machine control panel is inhibited") → must ONLY be done at an idle window (shift end / changeover / stopped machine), NEVER mid-production. **DEFERRED — not required to build:** the hand-typed CSVs (Mount Step) + ProductBOM already give placements-per-board + feeder→part. Revisit C1P bundle-pull later if we want an automated always-current source. Pull timing: at program-load / job start (C1 uploads need machine NOT in AUTO); trigger off **R1SEP** (PWB data selected) to re-pull + recompute per new job. NC "supply station number" = same id as parts-out Z field, counts align feeder-for-feeder.
Open: (b) qty-lookup LAN-outage behaviour — swap completes locally & sync later vs require qty before "done" (note: manual key-in may also serve as the qty fallback when parts control unreachable); (c) confirm auto-running + manual-actual split.

**Protocol (serial):** Uses the SI-E command set (manual MAN00000188, SI-E1000/E2000). STX/ETX framing, char-count, 2's-complement checksum, ETX. Default 9600 8?/7E1, RS-232C 25-pin HOST port. Command classes C/D/R/A. 7-second timeout.
- Enable real-time push per port with **`C5RO` — LETTER O, NOT ZERO** (⚠️ verified on real machines 2026-07-22: `C5R0` with a zero → rejected `A4E01` "unknown command"; **`C5RO` → acknowledged `A2` then `R1RO` "real-time ON"**. The manual's typeface makes O/0 indistinguishable and I had it wrong until live testing. Frame: `<STX>04C5RO83<ETX>`.) Fixed in LineDiag.ps1 and serial-test.html.
- **Board complete has TWO variants — count BOTH: `R0CT`** (continuous mode) and **`R0EP`** (one-cycle/step mode). Both observed live on real machines.
- **SI-F adds `A5` "BUSY" codes (not in SI-E manual): `A5E00`** processing another command, **`A5E01`** busy/retry when done, **`A5E02`** operator busy at machine. Command-sending must treat **`A5xx` = retry shortly** (distinct from `A4xx` = rejected). Also `A4E02` = off-line for SI-F C1.
- Parts-out event = **R2E03** (`R2E03S000NnnnnZnnnM000T000`). **Z = 3-digit supply-station/feeder number**. F209 (SI-F series) also emits **R2E04** on cassette/cart alternation. Expect repeated R2E02 (missed-pickup) during recovery → debounce.
- Feeder→part key = **Supply Allocation file** (`.SPL` serial / `.SP4` network). Maps supply-station# → **Part ID** (integer). `ALLOCATION:` records = `cell#, supply station#, part ID, alternate#, [alt stations…]`. Part ID → human part code needs a further lookup (Parts Data / library) — but here the operator hand-makes the folder file, so its format is the operator's choice.
