**Started 2026-09-07.** Danial wants to scope an SMT reel-delivery robot: an AMR that carries reels / bare-board packs from the store to the 5 lines. Candidate platform = **Reeman** (Chinese SLAM robot; doc `Downloads/robot/REEMAN SLAM WEB API 3.0-2023-10-16.en(1).pdf`, nav version RSN-v3.1.5, 14 pp).

**What the Reeman HTTP API gives (plain REST on the robot's LAN IP, no auth in the doc):**
- Nav: `POST /cmd/nav_name {point}` (go to a named calibrated waypoint), `/cmd/nav` (x,y,theta), `/cmd/nav_list` (multi-stop), `/cmd/cancel_goal`, `/cmd/charge {type,point}`, `/cmd/max_speed` (0.3–1.0 m/s).
- Status (poll, no push/websocket): `GET /reeman/nav_status` → `nav_result{state code name dist_to_goal mileage}`; state 1=started, 3=done (code 0 ok / -1 fail), 4=cancelled, 6=idle with reason codes (-2 e-stop, -4 point not found, -6 localisation lost…). `GET /reeman/pose`, `/reeman/base_encode` (battery %, chargeFlag, emergencyButton), `/reeman/speed`, `/reeman/position` (waypoint list with `type: delivery|avoid`), `/reeman/special_polygon` (speed zones), `/reeman/restrict_layer` (virtual walls).
- Map: set_mode 1=mapping/2=nav/3=incremental, save/apply/export/import/rename/delete map. Robot IP must NOT be on a 192.168.10.x segment (doc says third octet ≠ 10).
- Payload hooks: `/cmd/lock|unlock` (12/24V external power switch) and `/cmd/hydraulic_up|down` (jacking module). **No tray/drawer/lock-box API, no "arrived → wait for confirm" primitive** — the delivery handshake must be built by us (waypoint arrive → operator scan on PVS → next leg).

**Why:** the line PCs (LINE1..5PVS) + store are all on the same LAN, so the dispatcher can live on the NAS/MCS side and drive the robot with plain HTTP. The trigger source already exists: PVS parts-out (R2E03) + the exhaust-window prediction ([[pvs-partsout-expected-watchdog]]) and MCS StockOut issue rows ([[pvs-mcs-coordination]]).

**How to apply:** treat the robot as a Floor-Ai-style *proposer* for stock movement — it never writes StockOuts; MCS issue (INSERT) stays the store's act, PVS scan at the line stays the load event. Waypoints = one per line at the operator station (matching the manning-zone camera position, [[line-manning-vision]]) + "Store" + "Charging pile". Robot hostname/IP, model, payload and tray hardware still unknown — ask before designing the handoff.

**BUILT 2026-09-07 (not deployed).** Robot = flat open plate + pole display (photo), taught points: one per line + a store standby.
- Dispatcher lives in the **MCS app** (`MCS/app/Robot/*`; `/api/robot/status|call|send|home|charge|done|cancel|settings|points|events`; launcher tile → `robot.html`).
